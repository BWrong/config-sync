# 源目录采用镜像布局，而非文件名编码或清单文件

源目录中 `home/` 子树与 `$HOME` 逐路径对应（`home/.zshrc` ↔ `$HOME/.zshrc`）。chezmoi 用文件名编码属性（`dot_`、`private_`、`.tmpl`），清单文件方案用一个 `sync.yaml` 显式映射；本项目两者都不取，因为 v1 只有普通文件、没有模板与权限编码，文件名编码的全部复杂度都在购买用不上的能力，而清单文件会引入与真实文件并存的第二份真相。镜像布局的代价是：将来要支持模板或 per-file 属性（如 `private_`）时，必须给布局增加表达方式——可能是一个 `home/` 之外的目录，或每文件的边车元数据——而不是改文件名。

## Status

accepted

## Consequences

- 换布局要迁移所有已有用户的仓库，因此这条决定一旦有用户就无法低成本反悔。
- 不受管文件、被忽略的路径没有地方表达偏好，v1 只能靠"不在仓库里"来表示。
- `add` 的路径推导极简：目标路径减去 `$HOME` 前缀即源目录内路径，无需转义规则。
